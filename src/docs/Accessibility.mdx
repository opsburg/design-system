# Accessibility

The components target **WCAG 2.2 AA**, and the system checks itself.

## How it is checked

- **While you work:** the *Accessibility* panel in Storybook runs [axe](https://github.com/dequelabs/axe-core) on the current story and lists every violation, pass and item to review. Switch the toolbar to *Night* to check the dark theme too.
- **In CI:** `pnpm test:a11y` builds Storybook, opens every story in Day and Night, runs axe with the WCAG 2.0, 2.1 and 2.2 A/AA rules, and fails on any violation. A story with a known, accepted issue carries the tag `skip-a11y`, with the reason in a comment next to it.

## Rules the tokens already enforce

- Every text/background token pair holds at least 4.5:1 in both themes (lowest 5.4:1 in Day, 5.8:1 in Night).
- The focus ring `ring` is solid, 2px, and holds at least 3:1 on every surface.
- Brass `primary` is never text on the ground (2.5:1 on Day): text uses `primary-strong`.

## Rules for every component

- Every interactive control is a native element (`button`, `a`, `input`) or a Radix primitive, reachable by keyboard, with a visible `ring-2 ring-ring ring-offset-2` focus.
- Form fields wire label, description and error with `htmlFor`/`id`, `aria-describedby`, `aria-invalid`, `aria-required`; errors have `role="alert"`.
- A status is never color alone: a word sits next to every dot and badge.
- Decorative icons are `aria-hidden`; an icon-only button needs an `aria-label`.
- Motion respects `prefers-reduced-motion`.
- Every string a screen reader announces can be overridden through props, so the app can translate it.
